# OpenSLT 智能测试用例生成

_基于内网知识资料与 OpenAI-compatible LLM 的 Excel 系统测试用例草稿生成_

**文档版本：**V0.2

**文档状态：**需求草案，待评审

**编制日期：**2026-09-03

**适用产品：**OpenSLT 自动化测试平台

**目标用户：**测试人员、测试负责人、系统管理员

> **产品决策：** 第一阶段只生成可人工执行的 Excel 系统测试用例草稿；生成结果必须可追溯、可校验并由测试人员复核，不自动发布，也不生成可执行测试代码。

# 文档结论

- 在 OpenSLT 新增“智能用例”页面，提供需求上传、检索预览、生成任务、结果复核提示和 Excel 下载。
- LLM 通过内网 OpenAI-compatible 接口调用，需求正文和知识资料不得发送到未配置的外部地址。
- 知识资料由 OpenSLT 从内网 SVN 的白名单子目录增量同步；每个子目录独立检出，任何同步失败均不替换上一成功索引。
- 首版采用关键词与内网 embedding 的混合检索，不建设独立向量数据库、不微调模型；向量保存在本地 SQLite 发布快照中。

# 1. 文档概述

## 1.1 背景

盛立现有 knowledge 目录保存了需求规格、交易所业务资料、历史测试用例、测试报告、测试数据和少量既有生成结果。实地盘点共 1,815 个文件、约 1.15 GB，其中包含 863 个 XLSX、513 个 DOCX、55 个 PDF、65 个 CSV 和 148 个 TXT。资料量已经足以支持相似需求与历史用例检索，但格式、版本和字段结构并不统一。

抽样 120 个历史测试用例工作簿得到 101 种表头签名。差异既来自产品和自动化协议格式，也来自测试结果版本列。因此系统不能假设所有用例共享一个固定表头，必须区分“生成内容结构”和“Excel 输出模板”。

## 1.2 目标

- 缩短测试人员从需求理解到形成首版系统测试用例草稿的时间。
- 复用历史测试经验，减少遗漏正常、边界、异常、兼容、配置和升级场景。
- 让每条生成用例能够回溯到需求正文或历史资料，降低 LLM 编造风险。
- 输出沿用 Excel 工作方式，不改变现有用例评审、补充和执行习惯。

## 1.3 成功标准

| 维度 | 验收指标 | 目标值 |
| --- | --- | --- |
| 结构正确性 | 必填字段完整、编号唯一、步骤和预期可对应 | 100% |
| 事实可靠性 | 专家抽检不存在凭空编造的消息号、枚举、阈值或业务规则 | 严重编造 0 项 |
| 需求覆盖 | 关键需求点至少被一条用例覆盖 | ≥ 90% |
| 草稿可用性 | 抽样用例经轻量修改即可进入评审 | ≥ 80% |
| 检索有效性 | 基准需求的已知相关资料出现在前 10 条结果 | Recall@10 ≥ 80% |
| 安全性 | 未授权用户不可生成或下载；资料只发送到配置的内网模型 | 100% |

# 2. 用户与使用场景

| 角色 | 主要目标 | 权限边界 |
| --- | --- | --- |
| 测试人员 | 上传需求、确认检索资料、生成并下载 Excel 草稿 | 可创建和查看本人及团队生成任务；不可修改系统模型配置 |
| 测试负责人 | 评估覆盖度、识别遗漏并组织用例评审 | 与测试人员相同；评审结论仍在线下或既有流程完成 |
| 系统管理员 | 配置 SVN 白名单和内网模型、刷新索引、查看失败原因 | 可维护配置和索引；密码与 API Key 不回显 |
| 访客 | 查看已批准的现有平台数据 | 不可访问智能用例页面、生成任务或草稿文件 |

## 2.1 核心用户故事

作为测试人员，我希望上传一份新需求、选择业务产品和 Excel 输出模板，在确认系统检索到的历史资料后启动生成，并下载带“草稿待复核”标记的测试用例，以便在保留人工判断的前提下快速完成首版用例。

## 2.2 标准业务流程

**步骤-01** 管理员完成 SVN 知识源、白名单、内网 embedding/LLM 地址、模型名称和访问凭据配置，并建立知识索引。

**步骤-02** 测试人员进入“智能用例”页面，上传需求文档，选择业务类型、输出模板，并填写可选补充说明。

**步骤-03** 系统解析需求，展示文件名称、识别出的需求编号/名称、正文摘要和解析告警。

**步骤-04** 系统检索相关需求文档、历史测试用例和业务资料，展示来源路径与相关性顺序。

**步骤-05** 测试人员可取消不适合作为依据的资料，然后启动生成任务。

**步骤-06** 后台调用内网 LLM，接收结构化结果并执行字段、编号、来源和内容完整性校验。

**步骤-07** 生成成功后，系统保存 Excel 草稿及生成元数据；失败时保留可理解的错误原因。

**步骤-08** 测试人员下载 Excel，在人工评审中修订、补充和批准；系统不自动将草稿写入正式用例库。

# 3. 范围

## 3.1 第一阶段范围

- OpenSLT 新增“智能用例”页面和导航入口。
- 支持 DOCX、XLSX、PDF、TXT、MD、CSV 格式的需求输入；单文件上限默认 20 MiB。
- 支持 fut_mm、rem_two、rem_two_mm、tf_nf11 四类现有业务产品。
- 对 SVN 白名单目录中的可解析资料建立本地增量索引，并展示 revision、索引状态、成功数和失败数。
- 基于需求编号、标题关键词、产品目录、正文关键词和 embedding 相似度混合检索相关资料。
- 调用内网 OpenAI-compatible Chat Completions 接口生成结构化测试用例。
- 执行确定性校验，生成带草稿状态、来源说明和生成元数据的 XLSX。
- 保留生成任务、模型名称、输入摘要、引用来源、结果文件和审计记录。

## 3.2 第一阶段不包含

- 不生成 pytest、接口脚本、发单脚本或其他可执行自动化代码。
- 不自动执行生成用例，不连接生产交易环境，不自动判定测试通过或失败。
- 不训练或微调模型，不建设独立向量数据库。
- 不自动批准、发布或覆盖现有正式测试用例。
- 不解析 ZIP/RAR 内的测试工具和二进制资料，不支持旧版 DOC 或扫描图片 OCR。
- 不承诺一次生成覆盖全部业务知识；人工复核是正式使用前的强制步骤。

> **升级触发条件：** 首版直接采用本地 embedding 混合检索；只有当实测检索时延或容量超过 SQLite 应用层扫描能力时，才引入独立向量数据库。只有当结构化输出合格率无法通过提示词和校验达到目标时，才评估微调。

| source_refs | 支持本用例的需求段落或知识来源编号 | 引用必须存在 |

| NFR-008 | 兼容性 | 保持 Python 3.8+、RHEL 7.9、SQLite 开发库及现有 MariaDB/MySQL 生产约束。 | P0 |
| NFR-009 | 可观测性 | 记录任务耗时、模型响应耗时、检索条数、用例数、失败码和 trace_id；日志不记录完整正文。 | P1 |
| NFR-010 | 可访问性 | 上传、错误、进度、来源选择和下载均支持键盘操作与明确标签；生成状态不只依赖颜色表达。 | P1 |
| NFR-011 | SVN 网络安全 | HTTP 仅在管理员显式确认风险后允许，且必须使用受限来源主机与专用只读账号；迁移 HTTPS 后使用受信任的内网 CA，不提供“忽略证书错误”。 | P0 |
| NFR-012 | 索引可用性 | SVN、解析或 embedding 请求失败时不得替换上一成功的 SQLite 索引快照；旧索引仍可继续检索和生成。 | P0 |

# 7. 模型与提示词约束

- 接口协议：兼容 OpenAI Chat Completions；Base URL、model、API Key、timeout、max_tokens 可配置。
- 系统提示词固定声明角色、证据边界、输出 JSON Schema、禁编造规则、步骤预期对应规则和最大用例数。
- 需求正文和参考片段按上下文预算截取；系统必须优先保留需求关键章节、命中片段和表格行，不简单截取文件开头。
- 模型输出先作为不可信输入解析。禁止模型指定文件路径、公式、外部 URL、系统命令或权限操作。
- 模型名称和提示词版本写入生成说明，便于同一需求复现和对比。

# 9. 验收方案

## 9.1 功能验收

**FA-01** 未配置 LLM、embedding 或 SVN 知识源时，页面显示具体缺失项并禁止生成。

**FA-02** 管理员建立索引后，页面展示成功、跳过、失败数量，单个损坏文档不导致任务整体失败。

**FA-03** 测试人员上传合法 DOCX，确认需求信息和检索来源后能创建异步任务；刷新页面后状态仍可见。

**FA-04** LLM 返回合法结构时生成 XLSX；返回非 JSON、重复标题或空步骤时不给出半成品文件。

**FA-05** Excel 用例页字段完整、可编辑、无公式注入，生成说明页可追溯到模型、提示词版本和来源路径。

**FA-06** visitor 访问生成、任务详情和下载接口均返回 403；admin/tester 操作按要求记录审计。

## 9.2 SVN 与 embedding 验收

- 验证首次 checkout、定时 update、手动同步、无变化同步，以及文件新增、修改和删除；自动同步延迟不超过 30 分钟。
- 验证密码错误、网络超时、客户端缺失、working copy 冲突/本地修改/URL 不一致和任务重启恢复。
- 验证 HTTP 未显式允许时拒绝保存；HTTPS 不需要风险开关，证书不受信任时不得静默跳过校验。
- 验证非白名单目录不会检出、解析、向量化、检索或出现在来源引用中。
- 验证 SVN 密码和 embedding API Key 不出现在 API、审计、日志、任务载荷、进程参数、环境变量和 Excel 中。
- 验证新增/修改文件调用 embedding，未变化文件复用已有向量，删除文件删除对应向量；模型失败后旧索引仍可检索。
- 在 RHEL 7.9 内网测试机使用真实 SVN 和 embedding 服务完成验收，并记录 revision、向量维度、文件变化数和 Recall@10。

## 9.3 业务质量基准

以 knowledge 中“4128 上期所套利交易指令需求规格说明书”及其现有测试用例作为首个离线基准。验收不比较文案逐字一致，而比较需求点覆盖、事实准确、步骤可执行和历史遗漏补充能力。

| 检查项 | 方法 | 通过标准 |
| --- | --- | --- |
| 检索召回 | 查看前 10 条来源是否包含 4128 需求及同编号测试用例 | 已知相关资料命中率 ≥ 80% |
| 关键覆盖 | 按需求章节建立验收清单，检查生成用例映射 | 核心条目覆盖 ≥ 90% |
| 事实准确 | 两名熟悉业务的测试人员抽检至少 20 条 | 严重事实错误或精确值编造为 0 |
| 可执行性 | 检查前置、动作、数据和预期是否可直接操作 | ≥ 80% 仅需轻量修改 |
| 结构质量 | 自动扫描工作簿和结构化结果 | 必填完整 100%，重复标题 0，引用失效 0 |

# 10. 发布与运行约束

- 功能作为 OpenSLT 用户可见新增能力进入 RELEASES.json 的 unreleased/added。
- SVN/模型地址和凭据通过管理页面或部署配置维护，不在代码、样例或离线包中硬编码实际账号密码。
- RHEL 7.9 离线包必须包含 `subversion` RPM 及依赖和文档解析依赖；启动时执行 `svn --version --quiet` 就绪检查，并在无互联网环境完成后端测试、前端测试和生产构建。
- 生产启用前必须完成数据出域检查：除配置的内网 LLM 地址外不得产生外部网络请求。
