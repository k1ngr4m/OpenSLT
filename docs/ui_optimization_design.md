# OpenSLT 全局 UI 优化设计文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档目标 | 为 OpenSLT 全部 Web 界面提供统一、可实施、可验收的 UI 优化方案 |
| 设计方向 | 专业控制台 |
| 目标用户 | 测试人员、系统管理员、只读访客 |
| 适用技术栈 | Vue 3、TypeScript、Vite、Element Plus、原生 CSS |
| 优化方式 | 保留现有技术栈、路由、信息架构和业务流程，进行渐进式改造 |
| 设计参数 | 视觉变化 4 / 动效 3 / 信息密度 8 |
| 主题策略 | 深青色导航框架 + 浅色工作区，首期不增加全局深色模式 |
| 核心分辨率 | 1440 × 900，兼顾 1280 × 720、1920 × 1080 和 1024 宽度窗口 |

## 2. 设计目标

OpenSLT 是内网自动化测速与运维平台。界面优化的首要目标不是制造视觉冲击，而是让使用者更快判断系统状态、更安全地执行操作、更容易追溯任务过程。

本次优化需要达到以下结果：

1. 用户进入任意页面后，能够在 3 秒内识别页面名称、当前对象、核心状态和主要操作。
2. 高频操作集中在稳定位置，主操作、次操作和危险操作具有明确层级。
3. 运行状态、资源健康、日志级别和操作结果使用一致的语义表达。
4. 表格、表单、终端、日志和工作流编辑器形成同一套视觉系统。
5. 加载、空数据、错误、禁用、权限不足和危险确认等状态完整可见。
6. 移除当前 `body { min-width: 1100px }` 带来的硬性宽度限制，保证 1024 宽度可操作，窄屏可查看关键内容。
7. 不改变现有接口、路由、权限模型、表单字段含义和任务状态机。

## 3. 现状审计

### 3.1 已有基础

- 登录页已经使用深青色品牌背景、双栏布局和明确的安全提示，可作为品牌视觉起点。
- 主框架具备稳定的左侧导航、顶栏状态和账号区域，信息架构清晰。
- 页面已使用 Element Plus，表格、表单、对话框、步骤条和反馈消息的基础交互可复用。
- 运行详情已拆分工作流、日志、合约文件和采集详情组件，适合进一步统一样式。
- 配置编辑器、SSH 终端和数据库操作台已经形成专业工具型页面的功能基础。
- 部分页面已有骨架屏、空状态、错误提示和 `prefers-reduced-motion` 处理，可扩展为全局标准。

### 3.2 主要问题

| 类别 | 当前问题 | 影响 | 优先级 |
| --- | --- | --- | --- |
| 设计系统 | 全局样式仅包含少量通用类，颜色、间距、圆角和阴影大量散落在组件中 | 页面观感不统一，后续维护成本高 | P0 |
| 品牌一致性 | 登录页的品牌感明显强于后台，后台主要呈现 Element Plus 默认样式 | 登录前后视觉体验断层 | P1 |
| 信息层级 | 页面标题、说明、筛选、表格和操作区的纵向节奏接近，缺少明确层级 | 扫读速度慢 | P0 |
| 数据密度 | 工作台使用四张等宽指标卡，页面下半部大量空白 | 空间利用率低，缺少待办和异常信息 | P1 |
| 表格 | 缺少统一的筛选区、批量操作、分页、列密度、空状态和行操作规范 | 不同列表页行为不一致 | P0 |
| 表单 | 多个复杂表单仍使用固定宽度对话框，校验依赖消息提示 | 错误定位慢，长表单操作压力大 | P0 |
| 状态表达 | 状态标签、圆点、文本、进度条并存，中文与英文状态混用 | 状态判断不稳定 | P0 |
| 响应式 | 全局最小宽度为 1100px，侧栏固定 232px | 1024 窗口和分屏场景不可用 | P0 |
| 交互反馈 | 部分可点击表格行、图标按钮和链接缺少一致的悬停、按下与键盘焦点 | 可发现性和无障碍不足 | P1 |
| 空白与异常 | 部分表格仅显示“暂无数据”，加载失败主要依赖临时消息 | 用户不知道原因及下一步 | P0 |
| 文案 | 业务状态、时间格式、技术标识和操作文案缺少统一规则 | 理解和追溯成本增加 | P1 |
| 视觉负担 | 大量内容都放入“白底 + 边框 + 阴影 + 圆角”卡片 | 层级被过度容器化 | P2 |

### 3.3 必须保留的内容

- OpenSLT 名称、`SL` 标识、深青色品牌基调。
- 现有一级导航名称和路由结构。
- 管理员、测试人员、访客的权限边界。
- 运行、方案、场景、资源、日志、用户等核心信息架构。
- 表单字段含义、字段顺序和已有的安全提示。
- 运行步骤、状态机、日志与 `trace_id` 的可追溯关系。
- Element Plus 作为基础组件库，不再引入第二套 UI 组件库。

## 4. 全局视觉系统

### 4.1 设计原则

1. **状态优先**：状态信息的辨识度高于装饰效果。
2. **任务导向**：每页仅保留一个最明显的主操作。
3. **高密度但不拥挤**：压缩无效容器和重复留白，不压缩文字行高与点击区域。
4. **语义一致**：相同状态、相同操作、相同层级始终使用相同表现。
5. **渐进改造**：先建立令牌和基础组件，再逐页替换，避免一次性重写。
6. **克制动效**：动效只用于反馈、状态变化和层级切换，不用于纯装饰。

### 4.2 色彩令牌

在 `:root` 中建立语义变量，并通过 Element Plus CSS 变量映射使用。组件中不再直接新增无归属的十六进制颜色。

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `--ui-canvas` | `#F3F7F7` | 页面画布 |
| `--ui-surface` | `#FFFFFF` | 主要内容表面 |
| `--ui-surface-subtle` | `#EAF1F2` | 筛选区、次级区块、悬停背景 |
| `--ui-surface-strong` | `#DDE8E9` | 选中、分组标题、强调分隔 |
| `--ui-sidebar` | `#0D292E` | 左侧导航 |
| `--ui-sidebar-hover` | `#16383E` | 导航悬停 |
| `--ui-sidebar-active` | `#1D474A` | 当前导航背景 |
| `--ui-primary` | `#0E806F` | 主按钮、焦点、选中状态 |
| `--ui-primary-hover` | `#0B6B5E` | 主色悬停 |
| `--ui-primary-soft` | `#D9EFEA` | 主色弱背景 |
| `--ui-text-primary` | `#132B30` | 标题和主要内容 |
| `--ui-text-secondary` | `#5C7075` | 说明、元信息 |
| `--ui-text-tertiary` | `#819196` | 占位和弱提示 |
| `--ui-border` | `#D7E2E4` | 常规边框 |
| `--ui-border-strong` | `#B8C9CC` | 聚焦、表格分组边界 |
| `--ui-success` | `#187B61` | 健康、完成、成功 |
| `--ui-warning` | `#A86618` | 待确认、警告、部分成功 |
| `--ui-danger` | `#BD3F4B` | 失败、离线、删除 |
| `--ui-info` | `#356FA3` | 执行中、系统信息 |
| `--ui-terminal` | `#101C24` | 终端和日志背景 |

状态色只用于真实语义，不作为装饰色。普通操作只使用主色。所有文字与背景组合应达到 WCAG AA，对正文使用至少 4.5:1 的对比度。

### 4.3 字体与数字

- 中文界面字体：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif`。
- 不再将未自托管的 `Inter` 放在字体栈首位，避免不同终端出现不可控回退。
- 运行编号、IP、端口、时间、耗时、百分比、`trace_id`、命令和日志使用等宽字体：`"Cascadia Code", "JetBrains Mono", Consolas, monospace`。
- 表格数值启用 `font-variant-numeric: tabular-nums`，保证列内数字对齐。

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 26px / 36px | 650 | 页面名称 |
| 对象标题 | 20px / 30px | 650 | 运行编号、资源名称 |
| 区块标题 | 16px / 24px | 600 | 表格、面板、步骤分组 |
| 正文 | 14px / 22px | 400 | 默认界面文字 |
| 强调正文 | 14px / 22px | 600 | 关键名称和结果 |
| 辅助文字 | 12px / 18px | 400 | 时间、说明、次级信息 |
| 数据指标 | 30px / 36px | 650 | 仪表盘关键数字 |

### 4.4 间距、圆角与阴影

- 间距采用 4px 基础栅格，常用值为 4、8、12、16、20、24、32。
- 页面左右留白：1440 及以上为 32px，1024-1439 为 24px，低于 768 为 16px。
- 页面标题区到主内容间距为 20px，主内容区块间距为 16px。
- 控件高度统一为 36px，紧凑表格工具栏可使用 32px，主要按钮不得低于 36px。
- 圆角规则：输入和按钮 6px，标签 4px，内容面板 10px，对话框和抽屉 12px。
- 主内容面板默认仅使用边框，不使用阴影；悬浮菜单、对话框和固定浮层使用带青灰色倾向的轻阴影。
- 阴影建议：`0 10px 30px rgba(19, 43, 48, 0.10)`，不使用大面积纯黑阴影。

### 4.5 图标

- 继续使用现有 `@element-plus/icons-vue`，本次不新增图标库。
- 导航图标统一为 18px，按钮图标为 16px，空状态图标为 32px。
- 图标必须与文本或 `aria-label` 配合。仅图标按钮必须提供工具提示。
- 同一动作始终使用同一图标，删除、刷新、导出、返回和编辑不可混用。

### 4.6 动效

- 默认过渡时长 160ms，面板展开和抽屉切换为 220ms。
- 缓动统一使用 `cubic-bezier(0.2, 0, 0, 1)`。
- 仅动画 `opacity` 和 `transform`，不动画宽度、高度、顶部和左侧定位。
- 按钮按下使用 `transform: translateY(1px)`，表格行悬停只改变背景色。
- 加载使用与最终结构一致的骨架屏，不使用全页面旋转加载图标。
- 在 `prefers-reduced-motion: reduce` 下关闭非必要过渡。

## 5. 全局框架优化

### 5.1 左侧导航

- 桌面宽度保持 224px，较当前 232px 略紧凑；1024-1199 宽度折叠为 64px 图标栏。
- 导航分为“任务”“配置”“系统”三个视觉分组，但不改变现有导航名称和路由。
- 当前页面使用主色左侧 3px 指示条、弱主色背景和高对比文字，不只依赖图标颜色。
- 品牌区高度统一为 64px，保留 `SL` 标识、OpenSLT 和“自动化测速平台”。折叠时只显示标识。
- 账号区显示姓名、角色和退出入口。角色使用中文，不直接展示 `admin`、`tester`、`visitor`。
- 导航折叠状态保存在本地，不影响权限控制。

### 5.2 顶栏

- 顶栏高度为 52px，只承载全局状态、UTC 时间、帮助入口和当前用户快捷操作。
- “系统服务正常”改为可点击的服务状态入口，圆点只在表达实时健康状态时使用。
- UTC 时间按 `YYYY-MM-DD HH:mm:ss UTC` 展示，避免“UTC 时间”静态文字占位。
- `trace_id` 不应作为全局静态文案。仅在当前请求、日志或错误详情中按需出现。
- 顶栏采用 `position: sticky; top: 0`，滚动时保留上下文，层级低于对话框和抽屉。

### 5.3 页面标题区

统一结构为：面包屑、页面标题与说明、右侧主操作。详情页增加对象状态和关键元信息。

- 列表页示例：`测速运行` + “创建、排队并跟踪每一次测速执行” + `创建运行`。
- 详情页示例：`返回测速运行` + 运行编号 + 状态 + 创建时间 + 操作菜单。
- 页面仅允许一个主色实心按钮。次操作使用描边或文本按钮，危险操作放入更多菜单或危险区。
- 标题区在 768 以下纵向堆叠，操作区可横向滚动或收纳为菜单。

### 5.4 内容宽度

- 数据表、日志、终端和工作流编辑器允许使用全部可用宽度。
- 普通表单和说明内容限制在 960px 内，避免超宽阅读。
- 工作台内容最大宽度为 1600px，并在更宽屏幕居中。
- 不再使用全局最小宽度。确实需要宽内容的表格在自身容器内横向滚动。

## 6. 通用组件规范

### 6.1 按钮

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| 主按钮 | 当前页面唯一主要任务 | 创建运行、保存配置、确认执行 |
| 次按钮 | 可逆的辅助任务 | 取消、返回、刷新 |
| 文本按钮 | 表格行内低风险操作 | 查看详情、复制 ID |
| 危险按钮 | 删除、取消运行、强制停止 | 删除资源、终止运行 |

- 禁用按钮必须同时降低对比度并阻止交互，不能只改变颜色。
- 提交中保留按钮原有宽度，显示加载状态并防止重复提交。
- 危险操作确认框必须说明对象、后果和是否可恢复，确认按钮使用具体动词。

### 6.2 状态标签

建立统一 `StatusBadge` 组件，将后端状态映射为中文标签、语义色和辅助图标。

| 状态族 | 颜色 | 示例 |
| --- | --- | --- |
| 中性 | 灰 | 草稿、未开始、已取消 |
| 进行中 | 蓝 | 排队中、预检中、执行中、解析中 |
| 待处理 | 琥珀 | 待接线确认、待人工复核、等待资源 |
| 成功 | 绿 | 健康、完成、已连接 |
| 失败 | 红 | 预检失败、执行失败、解析失败、离线 |

- 标签文字始终使用中文，原始状态值可在工具提示或详情中显示。
- 不仅使用颜色区分状态。标签需同时包含文字，关键状态可配 14px 图标。
- 进度条只表达真实进度，不用作状态装饰。

### 6.3 表格

- 默认表头高度 40px，数据行高度 44px；日志和高密度配置表可使用 36px 紧凑模式。
- 表头使用弱青灰背景，文字为 12px、600 字重。
- 第一列优先放对象名称或编号，操作列固定在右侧并控制在 2 个可见操作以内。
- 超过 2 个行操作时使用“更多”菜单。危险操作不与主查看操作并列强调。
- 支持加载骨架、空状态、加载失败、无搜索结果四类状态。
- 数据超过单页容量时使用分页；分页位于表格右下角并展示总数。
- 筛选条件在重新进入页面时保留在 URL 查询参数中，便于分享和返回。
- 时间列统一格式；数值右对齐；名称、状态和文本左对齐。
- 可点击行须有悬停背景、键盘焦点和明确的详情入口，避免只有鼠标可用。

### 6.4 筛选栏

- 筛选栏位于标题区与表格之间，背景使用 `--ui-surface-subtle`，不额外加阴影。
- 第一行保留高频筛选和关键词，低频筛选放入“更多筛选”抽屉。
- 显示已生效条件数量，提供“重置”按钮。
- 查询操作可自动触发时使用 300ms 防抖；涉及远端或高开销查询时保留明确的“查询”按钮。
- 窄屏下筛选项改为两列或单列，不通过压缩输入框维持一行。

### 6.5 表单与复杂编辑

- 简单新建或编辑表单不超过 6 个字段时使用对话框。
- 超过 6 个字段、包含步骤或需要上下文预览时使用右侧抽屉或独立页面。
- 校验错误显示在字段下方，焦点自动移动到第一个错误字段。消息通知只用于整体结果。
- 必填标识、帮助说明、输入格式和敏感信息规则在字段附近呈现。
- 保存成功后明确告知保存对象，避免只显示“已保存”。
- 未保存内容在关闭、返回和切换对象前弹出确认。

### 6.6 空、加载与错误状态

| 状态 | 内容要求 | 主操作 |
| --- | --- | --- |
| 首次空数据 | 说明此处用途和创建后的结果 | 创建首个对象 |
| 筛选无结果 | 展示当前条件不匹配 | 清除筛选 |
| 加载中 | 与目标结构一致的骨架 | 无 |
| 加载失败 | 简述原因，保留错误追踪 ID | 重试 |
| 无权限 | 说明权限要求，不暴露敏感信息 | 返回工作台 |
| 功能不可用 | 说明资源停用或依赖不满足 | 查看资源或返回 |

错误信息使用直接、可行动的句子，例如“资源连接失败，请检查地址和认证配置”。不使用模糊的“操作失败”作为唯一信息。

### 6.7 通知和确认

- 成功消息停留 3 秒，警告 5 秒，错误在用户关闭前保留或提供详情入口。
- 同一操作不同时出现页面错误、消息通知和对话框三种重复反馈。
- 后台任务创建成功后，通知内提供“查看运行”入口。
- 可恢复删除优先说明回收位置；不可恢复操作要求输入对象名称或明确二次确认。

## 7. 页面级优化

### 7.1 登录页

保留当前双栏结构和深青色品牌背景，调整为更克制的专业入口。

- 左侧标题使用“盛立自动化测试平台”，下方增加一句具体说明：“统一管理测速资源、运行流程、实时日志和结果归档”。
- 删除纯装饰性大圆和过强网格，仅保留低对比线路纹理，表达测速链路概念。
- 右侧登录区保持 360px 内容宽度，表单错误在字段下显示。
- 提交按钮文案使用“登录”，安全语义由页面说明和 HTTPS 环境承担。
- 默认密码提示保留，但仅在初始账号或后端返回相关状态时强调。
- 适配 768 以下单栏布局，品牌区高度控制在 32dvh，保证表单无需大幅滚动。

### 7.2 工作台

工作台从“统计卡片集合”调整为“状态总览 + 待处理事项 + 最近运行”。

- 顶部摘要由 4 张同形卡改为一条数据概览带，显示运行总数、进行中、待人工确认、失败和健康资源。
- “待人工确认”和“失败”权重高于“已完成”，有数据时使用语义色和可点击入口。
- 主区域采用 8:4 栅格。左侧为最近运行，右侧为待办与资源异常。
- 最近运行显示运行编号、方案/场景、当前步骤、状态、更新时间和责任人。
- 右侧待办按紧急程度排序，包括接线确认、人工复核、资源离线和日志异常。
- 无待办时展示“当前没有需要处理的事项”，不保留大片空白卡片。
- “创建测速运行”仍是页面唯一主操作。

### 7.3 测速运行列表

- 增加状态、业务、方案、创建人、时间范围和关键词筛选。
- 默认按更新时间倒序，执行中和待确认任务可置顶，但需明确显示排序规则。
- 表格增加当前步骤、更新时间、执行人；进度仅在可量化阶段显示。
- 运行编号使用等宽字体，支持一键复制。
- 点击行进入详情，同时保留独立“查看”按钮以支持键盘操作。
- 创建运行由 620px 对话框改为右侧 560px 抽屉，依次完成方案、场景和执行资源选择。
- 资源选择项同时展示名称、地址、健康状态和占用状态。不可用资源禁用并解释原因。
- 创建前展示简短摘要，明确将锁定的资源和预计步骤数量。

### 7.4 运行详情

运行详情是优先级最高的核心页面，应围绕“现在发生什么、需要我做什么、为什么失败”组织。

- 顶部对象标题显示运行编号、中文状态、方案/场景、创建人、创建时间和总耗时。
- 右侧操作根据状态动态显示：开始、人工确认、重试步骤、取消运行、下载报告。只突出当前最重要动作。
- 工作流条固定在详情顶部下方，步骤支持完成、当前、等待、失败和跳过五种状态。
- 当前步骤具有清晰的边框和背景，失败步骤显示错误摘要和“查看日志”。
- 主内容采用 7:5 栅格。左侧显示步骤详情、输入输出和采集结果，右侧显示可筛选的实时日志。
- 日志面板在桌面端可固定，1024 以下改为底部页签或可展开抽屉。
- 人工确认使用高识别度行动面板，展示操作说明、风险、确认人和确认时间，不只使用弹窗。
- 失败状态在页面顶部提供问题摘要、失败步骤、错误时间、`trace_id` 和建议操作。
- 日志断流、自动重连和历史加载状态必须明确显示。
- 报告与产物按“报告、原始数据、解析结果、配置快照”分组，支持文件大小、校验值和下载状态。

### 7.5 方案与场景

- 方案列表与场景列表建立主从关系，避免多个同权重卡片重复堆叠。
- 左侧显示方案列表和业务筛选，右侧显示选中方案的基本信息、场景和默认资源。
- 方案启用状态、版本、场景数量和最近修改时间在列表中可扫读。
- 新建和编辑方案使用抽屉，复制操作在提交前允许修改名称。
- 场景按启用、草稿和异常配置分组，缺失必要资源时显示具体提示。
- 删除和停用分开处理。已有历史运行的对象应优先停用，删除确认说明引用关系。

### 7.6 工作流编辑器

- 页面采用三栏结构：节点库 240px、画布自适应、属性面板 320px。
- 1024-1199 时节点库和属性面板均可折叠；低于 1024 时属性面板使用抽屉。
- 节点卡片统一显示类型图标、名称、资源要求和校验状态。
- 连线、选中、悬停、执行中、完成和失败使用不同但一致的语义表现。
- 画布顶部提供保存状态、撤销、重做、缩放、适应画布和校验入口。
- 未保存、保存中、已保存和保存失败持续可见，不只依赖临时消息。
- 校验结果以问题列表展示，点击问题定位到对应节点。
- 节点配置长表单使用分组和折叠，不在窄面板中堆叠双列表单。

### 7.7 资源管理

- 增加资源类型、业务、健康、启用和占用状态筛选。
- 表格首列显示资源名称与类型，连接地址使用等宽字体，健康和占用分列展示。
- 操作列保留“打开操作台”和“更多”。编辑、连通性测试、停用、删除进入更多菜单。
- 新增资源的复杂表单改为 640px 右侧抽屉。数据库资源保留分步流程。
- 数据库连接摘要、远端主机、凭据、路径和能力配置使用清晰分组。
- 密码和私钥字段永不回显原值，编辑时明确提示“留空保持不变”。
- 连通性测试显示阶段、耗时和结果详情，避免仅弹出成功或失败消息。
- 停用资源前展示正在使用它的运行，禁止在占用状态下直接删除。

### 7.8 SSH 终端与配置管理

- 终端页面标题显示资源名称、类型、地址、健康和连接状态。
- 终端与配置管理使用分段切换，当前模式具有明显选中状态。
- 终端工具栏提供连接、断开、重连、复制、清屏和字体缩放。
- 连接中、已连接、重连中、已断开和认证失败使用统一状态条。
- 终端区域默认使用深色表面，周围不再额外叠加多层卡片。
- 配置文件列表、编辑器和元信息面板统一 36px 密度。
- 原始 XML 编辑建议后续接入 Monaco 或 CodeMirror；首期保留文本域时强化行号、错误定位和等宽字体。
- 未保存文件切换、重命名和删除均要求明确确认。

### 7.9 数据库操作台

- 查询与更新使用明显分区，更新区使用警告色边界和风险说明。
- SQL 编辑区采用等宽字体、行号和可调整高度，结果区占据主要空间。
- 查询结果表格支持粘性表头、横向滚动、行数统计、耗时和导出。
- `SELECT`、更新预览、确认执行三个阶段视觉上明确分隔。
- 更新确认展示影响行数、目标数据库、SQL 摘要和审计说明。
- 查询错误在编辑器下方呈现，并保留可复制的错误详情和 `trace_id`。

### 7.10 日志中心

- 页面顶部展示日志类型页签，筛选区固定包含时间范围、级别、来源、`trace_id` 和关键词。
- 应用日志、访问日志、运行日志和远端命令日志使用统一表格，但允许保存各自筛选方案。
- 日志级别使用文字和语义色，不将整行填满高饱和背景。
- 时间、级别、来源、事件、消息和追踪 ID 建立稳定列宽。消息列优先获得剩余空间。
- 点击日志行打开详情抽屉，展示完整消息、上下文、异常堆栈和关联对象。
- `trace_id`、`run_id`、`step_id` 可复制并可直接作为筛选条件。
- 实时日志提供“跟随最新”“暂停”“恢复”和连接状态。
- 审计日志强调不可修改属性，导出按钮旁明确提示“导出操作会被审计”。

### 7.11 用户管理

- 表格显示用户、显示名称、角色、状态、最后登录和最近修改。
- 角色和状态使用统一标签，账号名称使用等宽字体。
- 新建用户对话框保留为简单表单，编辑时用户名不可修改。
- 密码规则和角色权限摘要显示在对应字段附近。
- 禁用用户与删除用户分开。首期若无删除接口，不展示不可用入口。
- 当前登录管理员不能在无二次确认的情况下禁用自身。

### 7.12 未匹配路由与权限页

- 增加统一 404 页面，提供返回工作台和返回上一页入口。
- 权限不足不再静默跳转。展示短暂说明后提供可用入口，避免用户误判为页面故障。
- 后端不可用时展示全局服务异常页，并保留重试和故障追踪信息。

## 8. 响应式策略

OpenSLT 以桌面端为主，但必须支持分屏、笔记本和应急移动查看。

| 宽度 | 布局策略 |
| --- | --- |
| `>= 1600px` | 内容最大宽度 1600px，数据工具页面可全宽 |
| `1200-1599px` | 224px 侧栏，标准页面留白 24-32px |
| `1024-1199px` | 64px 折叠侧栏，双栏详情缩窄，次级面板可折叠 |
| `768-1023px` | 抽屉式导航，标题与操作堆叠，详情页改为页签或单栏 |
| `< 768px` | 支持登录、状态查看、人工确认和关键日志查看；编辑器与复杂配置提示使用桌面端 |

- 表格不通过压缩字体适应窄屏。优先固定关键列，其余列横向滚动或进入行详情。
- 终端和编辑器保持最小可操作尺寸，窄屏只读时明确提示。
- 触控目标最小 44 × 44px；桌面鼠标密集模式的可见控件不得低于 32px。
- 使用 `100dvh` 处理整页高度，避免移动浏览器地址栏造成跳动。

## 9. 无障碍与可用性

- 所有页面提供“跳到主要内容”链接。
- 所有交互元素可通过键盘到达，焦点顺序与视觉顺序一致。
- 全局焦点环使用 `2px` 主色描边和 2px 外间距，不能被 `overflow` 裁切。
- 状态不只依赖颜色，必须同时包含文字或图标。
- 图标按钮提供 `aria-label` 和工具提示，表单错误通过 `aria-describedby` 关联字段。
- 对话框打开后聚焦首个可操作元素，关闭后将焦点还给触发元素。
- 实时日志新增内容不自动打断屏幕阅读器；关键失败使用节制的 `aria-live` 通知。
- 正文对比度至少 4.5:1，大号文字和图形至少 3:1。
- 支持 200% 页面缩放，不出现主操作不可见或文本遮挡。

## 10. 文案与数据格式

- 页面标题和按钮使用简洁动宾结构，例如“创建运行”“保存配置”“重试步骤”。
- 成功反馈说明具体对象，例如“资源 REM-01 已保存”。
- 失败反馈包含原因和下一步，例如“SSH 认证失败，请检查用户名和凭据”。
- 时间默认显示本地时区，日志页明确显示 UTC；悬停可查看完整 ISO 时间。
- 持续时间统一显示为 `2 分 14 秒` 或 `238 ms`，不要混用多个格式。
- 文件大小统一使用自动换算的 KB、MB、GB。
- 技术标识保持原始大小写，如 `trace_id`、SSH、XML、CSV、PDF。
- 空值显示为短横线 `-`，未知状态显示“未知”，不可使用空白单元格表达。

## 12. 技术实施约束

- 保留 Vue 3、Element Plus 和现有 CSS 组织方式，不迁移到 Tailwind、Fluent、Carbon 或其他框架。

- 不改变 API 请求和响应结构，不改变路由地址，不改变权限判断。
- 不静默调整表单字段顺序、按钮业务含义和任务状态机。
- 不添加 GSAP、Motion、Three.js 等动效依赖。
- 不新增图标库，不手绘 SVG 图标。
- 不依赖在线字体、外部图片或 CDN，满足内网部署。
- 所有新组件必须包含默认、悬停、聚焦、禁用、加载、空、错误状态中的适用部分。
